## 2. 개선 사례 (발견 → 원인 → 고친 곳)

| 번호 | 발견한 것 | 어디서 발견 | 고친 곳 |
|---|---|---|---|
| 1 | 지표가 "수락률 1개"뿐이라 약했다 | 하늘님 의견 | PRD v1.1에서 지표 15개로 확장(5.1.2절), 한계도 명시 |
| 2 | 문제가 추상적이었다 | 하늘님 의견 | PRD v1.2에서 실제 글 6편 중 3편의 요약이 3자·3자·14자임을 근거로 추가 |
| 3 | 기획서에서 샘플 글 수를 이중으로 셌다("8편 + 지시문 시험 글", 8편에 이미 포함) | 기획서 재검토 | PRD v1.1 이후 문구 정정 |
| 4 | AI 요약을 수락해도 summaryAuto가 true로 남아 "요약 비움" 비율이 부풀 수 있었다 | 데이터 확인 | index.html 수정, ui-check UI-31 추가(31/31 통과) |
| 5 | 개요가 한 문장으로 길고, 문제와 해결의 연결이 약했다 | 리뷰어 피드백 | PRD v1.5에서 개요를 문제 → 해결 → 성공 판단 순서로 재작성 |
| 6 | 읽기 어려운 기호(§) 사용 | 하늘님 의견 | PRD v1.3부터 "N장·N.N절"로 교체, 1장은 표로 정리 |

## 3. 이번 과정에서 배운 점

- 기획서를 먼저 쓰고 구현하면, 구현 중 발견한 문제를 기획서에 다시 적게 된다. 위 4번이 그 예다.
- 숫자(수락률 77%)는 측정한 표본이 작아 방향 확인 수준이다. 그래서 한계를 문서에 같이 적었다.
- 리뷰 피드백은 문서 구조(개요 순서, 쉬운 말 설명)를 고치는 데 가장 효과가 컸다.

## 4. 아직 남은 일

- 하늘님 확인: AI Studio 단가, 강사 Q&A·승인, 3.5절 시나리오와 "번거로워서 비운다"는 가정이 실제와 맞는지.

- 문서 갱신: 이번 summaryAuto 수정을 PRD 6장·15장과 테스트보고서 v0.5에 반영.
