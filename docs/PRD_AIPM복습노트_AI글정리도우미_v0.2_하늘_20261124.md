**버전** v0.2 (내부용) · **작성일** 2026-11-24 KST · **작성자** 하늘 / Synnexedu Co · AI PM 2기 미니프로젝트
**변경** v0.1 → v0.2: 문제 정의를 근거·영향 경로·반증 조건 중심으로 재작성(2장), 나머지 장은 압축
**관련** [배포 블로그](https://yourrhdiddl.github.io/blog/) · [저장소](https://github.com/yourrhdiddl/blog)

## 1. 개요
관리자(나)가 복습 글을 발행하면 AI가 요약·제목 후보·태그를 **제안**하고, 반영은 내가 누를 때만 이뤄진다. 풀려는 문제는 "글을 다 쓰고도 요약 칸에서 멈추거나, 비워서 서두 문장이 요약이 되어 목록·검색·링크 미리보기가 동시에 나빠지는 것"이다.

## 2. 문제 정의
### 2.1 문제 진술
수업 직후 복습 글을 발행하는 관리자는 **요약**을 두 가지 중 하나로 처리한다. ① 글을 다 쓴 뒤 따로 한 번 더 쓴다(보상 없는 추가 작업). ② 비워 둔다. 비우면 코드가 **본문 앞 60자를 잘라** 넣는데(`index.html` 저장부), 복습 글의 앞 60자는 대개 경위·서두라서 **주제를 말하지 않고** 단어 중간에서 끊긴다.

### 2.2 영향 경로 (요약이 쓰이는 곳, 모두 코드로 확인)
| 쓰이는 곳 | 근거 | 요약이 나쁘면 |
|---|---|---|
| 갤러리 카드 문단 | `renderList` (결정 #23) | 카드만 보고 무슨 글인지 모름 |
| **글 검색** | `(제목+요약).includes(검색어)` | 본문·태그는 검색되지 않아, 요약에 없는 단어는 **글이 있어도 못 찾음** |
| 링크 미리보기 | `gen-og` `(요약‖본문).slice(0,120)` (#24) | 공유받는 사람의 첫인상 |
| 글 상세 리드 | `renderDetail` | 본문 첫 줄이 한 번 더 반복됨 |

핵심 피해는 **복습 글을 나중에 다시 찾지 못하는 것**이다(블로그의 존재 이유가 복습). 태그는 화면에 표시만 되고 검색·필터에 쓰이지 않아 현재 가치가 낮다(열린 질문 Q1).

### 2.3 현재 대안과 한계
| 대안 | 한계 |
|---|---|
| 직접 쓰기 | 발행 직전 추가 입력. 안 쓰면 아무 불이익이 없어 미룸 |
| 비워 두기(자동 60자) | 샘플 6편 모두 서두·경위 문장. 예: `AI는 어제의 대화를 기억하지 못합니다. 그래서 수업에서 알려준 세 가지 문서가 사람과 AI 모두의 기억 장`(직접 쓴 요약은 "시스템 프롬프트, 의사결정 문서, 실패 로그…") |
| 규칙으로 첫 문장 추출 | 첫 문장이 서두인 것이 문제라 해결 못 함 → **기각** |

### 2.4 왜 AI인가 / 왜 지금인가
요약은 "글 전체를 읽고 주제를 고르는 일"이라 규칙으로는 못 하고 언어 모델이 잘하는 일이다. 틀려도 피해가 작다(제안일 뿐, 승인 전 미반영). 과제 기간(11/24~25) 안에 만들 수 있고 기존 무료 구조를 유지한다.

### 2.5 검증 상태와 반증 조건 (정직한 한계)
지금까지의 근거는 **코드와 6편의 샘플 글**이며, 샘플은 임의 내용이라 통계가 아니다. 사용자가 1인이라 설문은 하지 않고, **11/25 오전까지 아래를 측정**한다. 기준은 측정 전에 고정한 임의값이다(사후 합리화 방지).

| 검증 | 방법 | 문제가 실재한다는 기준 | 미달 시 |
|---|---|---|---|
| V1 자동 대체 비율 | `ai-suggest` baseline 모드(구현 예정) | 글의 30% 이상이 자동 60자 | 10% 미만이면 "이미 직접 쓴다" |
| V2 직접 요약 작성 시간 | 글 3편을 시계로 측정, 중앙값 | 60초 이상 | 30초 미만이면 "자동화 가치 낮음" |
| V3 자동 요약의 주제 전달 | 자동 60자 vs 직접 요약을 보고 주제 맞히기(본인+1인) | 자동은 절반 미만 정답 | 대부분 맞히면 "60자로 충분" |

**V1·V2가 모두 미달이면 P1을 '약한 문제'로 기록**하고 이 PRD의 한계로 남긴다(구현은 시연용으로 유지).

### 2.6 최종 문제 정의와 성공 기준
> 수업 복습 글의 요약이 직접 쓰이지 않거나 서두 문장으로 대체되어, 관리자가 **나중에 복습 글을 검색·목록·공유 링크에서 찾고 알아보는 데 실패**한다.

성공 = 요약이 주제를 말하는 글의 비율이 오르고(수락률), 요약 작성 시간이 줄어든다(4장).

## 3. 해결 방안
글 저장 → AI가 **요약(120자 이내)·제목 후보 3개·태그 3~5개** 제안 → 관리자가 수락 / 고쳐서 수락 / 무시. AS-IS "직접 쓰거나 서두가 요약이 됨" → TO-BE "저장 후 제안을 클릭으로 반영". **범위 밖:** 독자용 챗봇(독자 수 불명), 실시간 응답, 자동 게시, 이미지 분석.

## 4. 가설과 지표 (페르소나: AIPM 수강생 겸 관리자 1인)
| 가설 | 지표 | 목표(가설) |
|---|---|---|
| H1 제안이 쓸 만하다 | 수락률 = (수락+고쳐서 수락) / 제안한 **요약·제목** 항목 | 60% 이상 |
| H2 작성 시간이 준다 | 요약 작성 시간(V2 기준값 대비) | 50% 단축 |
| H3 안정적이다 | 배치 성공률 / 실패 시 안내 | 95% 이상 / 100% |

수락률은 `aiFeedback` 필드로 자동 기록한다. 표본은 글 10편 안팎이라 통계 검증이 아니다. 화면 용어는 「AI 제안」으로 통일한다.

## 5. 기능·비기능 요구사항
| ID | 기능 | 동작 |
|---|---|---|
| F1 | 제안 요청 | 글쓰기에서 「AI 제안 받기」(기본 켜짐) → 저장 시 `aiStatus:pending` |
| F2 | 제안 생성 | GitHub Actions 배치(15분 주기·수동 실행)가 AI 호출 → `aiSuggest` 저장, `ready`/`failed` |
| F3 | 확인·반영 | 글 화면 제안 카드에서 항목별 선택. **클릭 시에만** 제목·요약·태그 변경 |
| F4 | 실패 처리 | 1회 재시도 후 `failed`, 「직접 입력」 안내 |
| F5 | 상한 | 하루 20건, 텍스트만 6,000자, 이미지 제외 |

**비기능:** 키(AI·서비스 계정)는 GitHub Secrets에만 둔다. AI 결과는 `esc()`로만 화면에 넣는다. 배치는 `ai*` 필드만 쓴다. 제안 지연 최대 15분(수동 실행으로 단축). 비용은 월 5,000원 이하 목표, 모델 단가 미확인.
