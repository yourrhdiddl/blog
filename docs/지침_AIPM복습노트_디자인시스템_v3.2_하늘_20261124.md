# AIPM 복습 노트 · 디자인 시스템 (v3.2 · 민트·도트 + 사진 갤러리 + 본문 사진 블록 + 읽기 카드)

> 목적: 블로그 화면의 색·글꼴·모양 규칙을 한곳에 적어 두어, 누가 고쳐도 같은 모양이 나오게 한다.
> 기준: v3.0(2026-11-24)은 Drive 디자인 CSS와 사용자가 확정한 시안을 따른다. 결정 #49(결정 #37 흑백 에디토리얼을 대체). 사진 갤러리·글쓰기 편집기·본문 사진 블록 절은 v2.x 규칙 그대로이며, 색만 위 표를 따른다.
> v3.1·v3.2(2026-11-24, 결정 #52·#53)는 아래 "v3.1·v3.2 변경" 절이 위 원칙과 다를 때 **그 절이 우선**한다(예: 글 상세 카드에는 그림자가 있다, 버튼 테두리는 옅은 선).
> 옛 규칙(v2.2 흑백, v0.4 파스텔)은 이 문서 맨 아래 "이전 버전"에 요약만 남긴다.

## 원칙
1. 색은 민트 계열 + 연한 청회색 바탕. 값은 아래 표(라이트/다크 두 벌)만 쓴다. 노랑 형광펜 규칙(v2.2)은 없어졌다.
2. 구획은 1.5px 실선(--line)과 3px·1.5px 점선(--mint2)으로 나눈다. 카드는 그림자 없이 테두리만, 호버하면 테두리가 민트로.
3. 글 목록의 첫 카드(최신 글)만 가로로 크게 보여 주고 ‘NEW’ 알약을 붙인다. 7번째·10번째 카드는 2칸 폭(글이 많을 때만 의미가 있음).
4. 영문 제목은 Hanken Grotesk, 한글과 본문은 Pretendard. 자간은 제목 -0.03em, 본문 -0.01em, `word-break: keep-all`.
5. 누르는 것은 높이 44px 이상. 공개/나만보기는 색뿐 아니라 글자로도 구분한다. 오류는 색과 문구를 함께.
6. 방문자 기기가 다크 모드면 자동으로 다크 값으로 바뀐다(`prefers-color-scheme`, 수동 스위치는 없음).

## 본문 사진 블록 (v2.2, 결정 #43~#47)
- 구조: `figure.pf` 안에 사진(`img`) 1~3장 + `figcaption`(사진 설명, 13px, mute 색, 가운데 정렬). 설명이 비면 저장하지 않는다.
- 한 장: 가로 폭에 맞추고 원본 비율 유지. 여러 장을 한 번에 고르면 3장씩 한 묶음: `pf g2`(2열) / `pf g3`(3열), 간격 6px, 사진은 정사각형(`aspect-ratio:1/1; object-fit:cover`)이라 원본 가장자리가 잘릴 수 있다. 5장이면 3열 한 줄 + 2열 한 줄.
- 넣는 위치: 커서가 있는 문단을 둘로 갈라 그 사이에 넣고, 사진 뒤에 글 줄을 이어 만든다. 커서가 없으면 맨 아래. 붙여넣기·끌어다 놓기도 같은 규칙(끌어다 놓기는 놓은 자리).
- 선택: 사진을 누르면 3px 민트 윤곽선과 ink 바탕 알약 버튼 ↑ ↓ ✕(40px). 묶음에서는 누른 사진 한 장만 윤곽선이 생기고 ✕/Delete는 그 한 장만 지운다(남은 사진 수에 맞춰 열 수가 줄고, 한 장이 되면 일반 사진). 묶음 전체의 ↑↓는 묶음을 위아래로 옮긴다.
- 순서 바꾸기: PC는 사진을 끌어 놓는다(놓을 자리에 민트 표시선). 모바일은 ↑↓ 버튼(끌기 미지원). 묶음 안에서 사진 순서 바꾸기는 지원하지 않는다.
- 키보드: 설명 칸에서 Enter = 사진 아래 글 줄로 이동. 선택된 사진에서 Delete/Backspace = 삭제. 키보드만으로 사진을 선택하는 기능은 없다.
- 보안: 저장·표시 모두 `clean()`을 거친다. `FIGURE`/`FIGCAPTION` 허용, `class`는 사진 개수로 다시 만든다(`pf`/`pf g2`/`pf g3`), 편집용 속성·버튼은 저장되지 않는다(결정 #44).
- 보기: 글 상세에서 본문 사진을 누르면 크게 보기(1 / N), 목록의 '사진' 탭에도 모인다.

## v3.1·v3.2 변경 (결정 #52·#53)
**버튼:** 검정 테두리를 쓰지 않는다. 기본 버튼은 1.5px 옅은 선(--line)과 카드 배경, 호버하면 테두리가 민트(--mint2)와 연한 배경으로. 주요 버튼(.primary)은 테두리 없이 민트 배경. 삭제 계열(.danger)은 위험색 글자와 옅은 위험색 테두리. 글쓰기 버튼(우하단)과 「공유 링크 복사」는 이모지 없이 글자만 쓴다.
**글 상세 본문:** 폭 720px 안쪽, 글자 1.125rem(모바일 1.0625rem), 행간 1.95, 문단 아래 간격 1.4em. 소제목(h3)은 1.3rem에 왼쪽 4px 민트 막대, 인용문은 연한 배경(--soft)에 왼쪽 4px 민트 막대, 목록 마커는 민트.
**글 상세 카드 (v3.2):** 글 전체를 큰 흰 카드(--card)에 담는다. 모서리 24px(모바일 18px), 안쪽 여백 44px 52px(모바일 26px 20px), 최대폭 820px, 1px 옅은 선과 옅은 그림자(0 10px 32px, 라이트 7%·다크 28%). 상세 화면일 때만 페이지 배경을 --soft로 바꿔 카드와 구분한다. 이전/다음 글 버튼은 카드 안에서 --soft 배경. (원칙 2의 "그림자 없음"은 이 카드에는 적용하지 않는다.)
**홈 상단:** 소개·추천 영역을 압축해 소개, 추천, 탭이 한 화면에 보이게 한다. 카드 제목 1.125rem, 요약은 2줄(모바일 3줄)까지 보이고 넘으면 말줄임.
**글쓰기 화면:** 입력 사이를 26px 간격으로 나누고, 「AI 제안 받기」는 연한 배경 박스(체크박스 18px)로 묶는다. 본문 입력칸 최소 높이 340px. 임시저장 안내 막대(--soft 배경, 「이어쓰기」「버리기」)와 저장 상태 문구(회색 .8125rem)를 둔다.
**수정·휴지통:** 상세 상단 관리자 줄에 작은 버튼(높이 36px) 「수정」「휴지통으로 보내기」. 휴지통 행은 카드(1.5px 선)에 삭제 전 공개범위 배지와 "N일 뒤 영구삭제", 「복구」「지금 영구삭제」. 삭제 동작은 첫 클릭에 버튼 글자가 "한 번 더 누르면 …"으로 바뀌고 4초 안에 한 번 더 눌러야 실행된다.
**토스트:** 여러 개가 겹치면 아래에서 위로 쌓는다(개당 56px). 다크 모드에서 글자색은 --paper, 위험색은 #f0877b.

## 알려진 한계 (정직하게)
- 색 대비는 계산식으로 구했고 실제 화면 도구로 재검증하지는 않았다. 노이즈 겹침(body::after)이 대비를 얼마나 깎는지는 측정하지 않았다.
- v3.0은 로컬 Playwright(가짜 Firebase)로만 시험했다(라이트·다크 44/44, 가로 넘침 없음). 실제 휴대폰·실제 글 수에서의 모습은 미확인. 7번째·10번째 카드 2칸 규칙은 글 개수에 따라 어색할 수 있다.
- 폰트 파일(`fonts/PretendardVariable.woff2`)이 없으면 CDN을 쓴다. Hanken Grotesk는 Google Fonts 연결이 필요(실패해도 Pretendard로 대체).
- 대표 이미지가 있는 글 카드 썸네일의 흑백 처리는 v3.0 민트 테마와 어울리는지 사용자 의견을 아직 못 받았다(v2.0 규칙이 남은 것). 갤러리 사진은 컬러.
- 사진 용량은 합성 테스트 사진으로만 확인했다. 실제 휴대폰 사진(수 MB)을 900px로 줄였을 때의 크기와 글 한 편에 몇 장까지 들어가는지(약 4장 추정)는 확인이 필요하다.
- 본문 사진 블록은 컴퓨터 화면 기준으로 시험했다. 휴대폰에서의 3열 묶음·선택 버튼 모양, 되돌리기(Ctrl+Z) 연동은 확인하지 못했다.
- v3.1·v3.2의 모양은 Playwright(가짜 Firebase)로 라이트 모드에서만 자동 확인했다. **다크 모드 자동 검증은 하지 못했다**(테스트 도구가 색 모드 전환을 지원하지 않음). 실제 휴대폰과 실제 사진을 넣은 글 상세 카드는 하늘님이 직접 확인하기 전이다.
- 글 상세 카드 밖 영역(글쓰기·휴지통 등)은 카드 규칙이 적용되지 않는다. 필요하면 결정로그에 먼저 적고 확장한다.
